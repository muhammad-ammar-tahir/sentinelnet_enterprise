# 11 — Known Issues & Honest Limitations

> This document lists known gaps, cosmetic features, and platform constraints in the current codebase. Everything here is accurate as of the last commit.

---

## KI-01 — MFA Checkbox Is Cosmetic

**File:** `frontend/src/pages/LoginPage.tsx`

The "Enable MFA" toggle on the login screen does nothing at runtime. It toggles UI state only. There is no TOTP, FIDO2, or SMS challenge behind it.

**Impact:** Users who enable MFA still log in with username + password alone. No second factor is enforced.

**Fix required:** Implement TOTP via `pyotp` on the backend (`POST /api/auth/mfa/verify`), store TOTP secret in `users.totp_secret`, enforce challenge after password check.

---

## KI-02 — Training Data Is Synthetic Only

**File:** `ai_models/generate_training_data.py`

All 10,000 training rows are generated by injecting Gaussian noise around hand-tuned centroids for 5 fault classes. No real Mininet traffic was captured and labelled.

**Impact:** Accuracy figures in `evaluation.json` and `docs/10-TESTING-EVALUATION.md` reflect synthetic-distribution performance only. Real-world accuracy is unknown and likely lower.

**Expected resolution:** Capture real Mininet traffic during fault injection experiments and retrain on the captured dataset before claiming production-ready accuracy.

## KI-03 — Ryu / Mininet Requires Linux or WSL2

**Files:** `backend/controller/sdn_controller.py`, `network_simulation/topology.py`

Ryu and Mininet are Linux-only programs. On native Windows you will see:

```
httpx.ConnectError: [WinError 10061] No connection could be made because the target machine actively refused it
```

when the backend tries `GET http://127.0.0.1:8080/stats/switches`.

Similarly, `POST /api/topology/fail` will return `503 Service Unavailable` with message:
```
Cannot inject real failure: Mininet is not running — cannot inject real failure.
```
The endpoint strictly avoids mutating database state unless a real network cut is verified.

**This is expected.** The backend degrades gracefully: `is_controller_alive()` returns `False`, recovery actions move to `escalated` status, failure injection reports 503 instead of manufacturing fake DB success, and the dashboard shows the controller/simulation as offline.

**Fix:** Run the full stack in WSL2 or a Linux VM for end-to-end flow installation.

## KI-04 — Docker Compose Exists but Dockerfiles Do Not

**File:** `docker-compose.yml`

`docker-compose.yml` references `Dockerfile.backend` and `Dockerfile.frontend`, which do not yet exist in the repository. Running `docker compose up` will fail at the build step.

**Workaround:** Run each service directly on the host (see Quick Start in README).

**Fix required:** Author `Dockerfile.backend` (Python 3.11-slim base, copy requirements, `pip install`, copy backend/) and `Dockerfile.frontend` (Node 18-alpine base, `npm ci`, expose port 5173).

## KI-05 — Frontend Has No Component Tests

**Directory:** `frontend/src/`

The TypeScript compile (`npm run build`) is used as the only frontend correctness gate. There are no Vitest or Jest component tests for any React component, hook, or context.

**Impact:** Regressions in UI logic (e.g., broken WebSocket reconnect, bad incident table sort) are only caught by eye.

**Fix:** Add `vitest` + `@testing-library/react` and write tests for `AuthContext`, `useIncidents`, and `TopologyMap`.

## KI-06 — Recovery Time Is Dominated by Ryu Retry Timeouts

**File:** `backend/controller/sdn_controller.py`

Each Ryu API call times out after 5 seconds. With 3 DPIDs and 3 retries per DPID the worst-case penalty is 45 seconds of pure timeout before the engine escalates. The measured `recovery_time_ms` in the demo (~54 s) is almost entirely this timeout overhead, not actual SDN rerouting latency.

**Impact:** The recovery time KPI does not reflect the speed of OpenFlow rerouting; it reflects network unavailability.

**Fix:** Reduce `httpx.AsyncClient(timeout=5)` to `timeout=1` in production, or implement a circuit-breaker that skips DPIDs known to be unreachable.

## KI-07 — Host h4 Is Seeded Without a Link

**File:** `backend/database/seed.py`

Device `h4` is inserted into the `devices` table but no link connects it to any switch. The topology graph therefore has an isolated node. PathSelector correctly ignores it (it has no edges), but the topology visualisation renders it as a floating orphan.

**Fix:** Add `{"src": "h4", "dst": "s3", "src_port": 1, "dst_port": 4}` to the seed links.

## KI-08 — Audit Log Seed Is Not Idempotent on `created_at`

**File:** `backend/database/seed.py`

The audit log entries are seeded with `datetime.now()` timestamps. Re-running `python -m backend.database.seed` on a database that already has users produces duplicate audit log rows with new timestamps. The users themselves are skipped (idempotent), but `audit_logs` are not checked for duplicates.

**Impact:** Cosmetic only — running the seed script twice inflates the audit log count.

**Fix:** Add an existence check before inserting each audit log row, or use `INSERT ... ON CONFLICT DO NOTHING` with a unique constraint on `(user_id, action, created_at::date)`.

---

## KI-09 — WebSocket Refresh Tokens Are Not Renewed Automatically

**File:** `backend/ws/manager.py`

A WebSocket connection is authenticated once at connection time. If the JWT access token expires (15-minute window) while the WebSocket is open, the connection continues to work — the server never re-validates the token mid-session.

**Impact:** An attacker who steals a token can keep a WebSocket alive past the token's expiry.

**Fix:** Add a periodic server-side re-validation step (e.g., every 10 minutes, verify the token is still valid and the user is not revoked) and close the WebSocket with code 1008 if validation fails.

---

## KI-10 — `prometheus.yml` Is Not Included in Repository

**File:** `docker-compose.yml` mounts `./prometheus.yml`

The Prometheus scrape configuration file is referenced by the compose service but does not exist in the repository. The Prometheus container will fail to start without it.

**Fix:** Add a minimal `prometheus.yml`:

```yaml
global:
  scrape_interval: 15s

scrape_configs:
  - job_name: "sentinelnet-backend"
    static_configs:
      - targets: ["backend:8000"]
```

## ~~KI-11~~ — RESOLVED: Hardcoded JWT Secret in `backend/config.py`

**Status: ✅ Fixed in second code-quality pass.**

The `JWT_SECRET` field previously had a hardcoded default (`"sentinelnet-super-secure-production-jwt-secret-key-2026"`). This is now fully removed:
- **Production:** raises `RuntimeError` at startup if `JWT_SECRET` env var is missing, < 32 chars, or matches any known default.
- **Development:** logs a loud `WARNING` and applies an insecure placeholder; app continues.

## ~~KI-12~~ — RESOLVED: SHA-256 Fallback in `backend/database/seed.py`

**Status: ✅ Fixed in second code-quality pass.**

`hash_password()` previously fell back to `hashlib.sha256(salt + password)` if `passlib` was unavailable. This silently created weak hashes. The fallback is now replaced with a `RuntimeError` that blocks seeding until `passlib[bcrypt]` is properly installed.
